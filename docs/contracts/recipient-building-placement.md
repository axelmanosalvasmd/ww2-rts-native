# Internal recipient building placement

This is a Rust provider, with no new socket field, C export or approved ABI signature. `building_placement::check_recipient` takes a decoded `ClientView`, building kind and ground point. It reads only the delivered start map, remembered cells, units, teams, nodes, smoke and public weather. It returns the existing `Placement` value: optional denial, snapped centre, top-left cell, footprint cells and selected resource-node index. It has no access to a `Match` or undisclosed actors.

The placement kernel is shared with ordinary Build and implements `reference/ww2-rts/shared/sim.js:3277-3313` at `e4e579a`: footprint rounding, sight before blocked-ground reasons, node reservations, coastal water within two cells, grade and living-ground occupancy. Denials retain `blocked`, `notVisible` and `coast`. The recipient adapter uses the ordinary sight rule in `shared/sim.js:1744-1751`, supplied with already-delivered weather and grounded-aircraft flags. `client/main.js:1295-1298` establishes the preview's shared-rule intent. The native adapter fills the public facts omitted from `client/availability.js:187-199`; it changes no canonical visibility rule. Equivalent supplied facts produce the same placement result. Rounded recipient coordinates and undisclosed occupancy can still make a preview differ from authoritative admission, as in the prototype; Build always checks again.

World recipient placement returns an explicit deferred error. Every-cell visibility, territory and railway preview equivalence in BASE-27 remains deferred with running World admission. Detached World placement component tests inherited from #336 are narrower evidence. IF-04's C delivery remains separate.
