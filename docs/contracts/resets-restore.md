# Ordinary room AI resets and save restoration

Baseline: prototype `e4e579a838aabae3b1d9dadbc17a0a87147bc52d`. Owner decisions I, J and L recorded in #5 apply. Hermes' exact-head runtime acknowledgement remains required before merge. This extends the private [save format](save-format.md) and reuses [spectator delivery](spectators-v0.md).

Each attached room owns a `SeatCommander` and `HumanObservationMemory` per simulation seat. Human seats keep fresh inactive helpers; AI seats run the existing human-style commander after each ordinary simulation step. Requested observations are collected for all AI seats before any action. They are detached, recipient-filtered views, collected only on the room's snapshot beat. Canonical vision checks remain in the producer. The producer accepts odd ticks because adaptive snapshot cadence can deliver there, as in `server/room-tick.js:13-21` and `shared/ai-schedule.js:28-35`. Input attempts enter the existing canonical next-tick queue. Support attempts use the same exported capability list as ordinary recipient snapshots; #369 supplies the complete ordinary flight/event lifecycle.

A seated human token takeover replaces all three private owners: strategic policy, observation memory and commander attention/input timing (`server.js:596-602`). It preserves the person object, deny budget, RTT and accepted canonical orders. Only the returning seat resets. Replaced sockets still receive exactly `{t:"replaced"}` and close; late messages and closes keep their existing membership guard. A new match or restart constructs fresh owners for every seat (`server.js:393-404`). No helper field is sent to a client.

Saves retain the existing seven root keys and version 1. Human-only saves still write `ai:null`. Mixed and AI-only rooms write #392's slot-indexed tagged AI memory array. Only AI seats contribute entries. The policy's strategic RNG and observation contacts survive; the separate camera, motor timing, queued input actions and delivered packet restart (`shared/ai.js:159-165`, `shared/ai-human.js:35,51-65`, `server/saves.js:18-26`). A missing/null `ai`, a missing/null array entry, and a missing/null AI difficulty use fresh memory and Normal difficulty. No new required field is added. Malformed present memory, invalid difficulty or another seat/match binding is refused before room publication.

Load preserves the prototype's two assignment passes, skipping saved AI seats in both: match all human tokens first, then assign remaining connected people in present order. Unmatched saved humans wait offline. Every unused connected human becomes a spectator (`server.js:439-445`). AI seats restore their saved name, level, team and faction without a socket. Human helpers start fresh after AI memory restoration (`server.js:447-448`). Spectator starts retain the existing exact prototype shape and full-map view from #372, with no new recipient fields (`server.js:450-455`).

The replacement room, private owners, saved event/ending state and starts are prepared before publishing. The playing lobby precedes starts. Load opens a host pause naming the loading person, including a person who becomes a spectator; slot identity is relevant only to drop pauses. All recipients receive their start and pause before an advancing callback. The room's current host resumes it through the existing message. AI seats count as online for pause and snapshot lists, have ping `-1`, and never become away merely because they have no socket (`server/room-tick.js:30`, `server.js:204-206,493-498`).

The configured private Conquest host can use the existing `addAi` and `level` messages in the lobby and start/restart two opposing commanders, including AI seats. All-AI rooms can be hosted by their spectator. The private-room, standard-army, mode, seed, weather and two-seat restrictions remain. World, Horde, FFI and C headers are outside this change. No new wire message or field is introduced.
