# Bounded scripted planner and real caller: Source/API plan

Current verified prerequisites are Default caller compiled `07250fdf` / docs `262926e` and Commander provider/policy compiled `e7f1b1f` / docs `be1cb2c` (PR #157). This is a plan, not an implemented integration or a full AI claim.

## Actual source boundary

- shared/ai-schedule.js: planner uses fixed thinkEvery, owner*13 staggering, wantsView only in the four-tick window before a due think, and observes only on sent beats. aiTick observes every selected seat before any seat acts. Its default ordinary brain is ai-human commander; only the Horde director defaults to scripted planner. Explicit planner seats are supported by playMatch.
- server/room-tick.js runs step, then aiTick, then snapshots. server.js:403-404 initializes AI views at clock zero, without an AI act there. playMatch follows the same initial observation, then step before act. Fixed two-tick delivery belongs to the headless schedule; room snapshots may adapt through the external meter.
- ai-human.js owns camera, reaction/notice delays, seeded timing, input queues and attention/input caps. None of these is implemented by the current native bounded scripted planner. Do not register that planner as a replacement for ordinary room AIs.
- sim.step owns vision at ticks 1,5,9. The checked native caller already matches it. Existing tick_opening_commander has a standalone fallback vision update and unconditional even-tick observation; the real caller must not use those ownership shortcuts.

## Proposed first bounded slice

Use a trusted explicit scripted-brain configuration, with no room/server activation or wire change. Preserve the existing isolated Ai(owner) stream and the delivered, detached observation. Cold startup produces the clock-zero view but does not run the policy. After each actual completed simulation step T, deliver wanted observations for registered scripted seats, then plan in fixed slot order. Act only at the source due tick, using the latest delivered view. Ordinary odd due ticks retain the prior even delivered view. Source's default logical sent beat also becomes true on a winner, so a final odd due tick can deliver a fresh wanted view. Scripted aiTick does not apply the human commander's live out/winner filter: delivered me.out gates policy, while canonical command admission can reject attempts against newer live out/winner state. Do not silently suppress those attempts or their draws.

Queue attempted commands for boundary T+1 through the one existing OrderQueue. Its dispatcher applies them at Game clock T before the next simulation clock advances, matching source command activation before step(T+1). Source snapshots immediately after aiTick can already show accepted command state; this first core slice must describe its queued-frame boundary and must not claim that network snapshot behavior. Transport delivery acknowledgment remains with its owner.

The sole tick owner supplies the exact post-step producer call site and remains the only match_tick writer. The consumer never repeats vision, path scheduling, clock advance or simulation phases. AI deferred/unsupported work cannot turn a completed simulation into a fake successful actuator or conceal a failed command. The proposed post-step result contains the completed simulation report and a separate AI outcome. Producer admission failure preserves queue, private policy and RNG state; it cannot return an ordinary simulation error suggesting that the completed step rolled back. Record logical delivered observation separately from planning publication, and explicitly mark processed T so retries cannot step or plan it twice. Root must approve the receipt, retry and per-seat versus whole-pass failure contract before edits.

The current queue assigns no separate AI namespace. OrderKey issuer and sequence are trusted caller-owned. The host must reserve a collision-free sequence range for the AI seat at the actual next boundary, respecting processed history as well as already-pending and future keys. Never overwrite, reassign or restart an issuer's sequence. Stage the whole range, queue capacity, policy and RNG publication before committing any of them. The policy emits typed intents only; source commands carry no native issuer or sequence metadata.
