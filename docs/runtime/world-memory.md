# Internal World recipient knowledge

WorldRuntime owns one lazy WorldMemory. Each team keeps accepted cells in first insertion order, stable row revisions, remembered region and wreck rows, and a shared RouteKnowledge World projection. Each commander keeps its own terrain delivery cursor. Route projection uses a separate team cursor. Full reads and reconnect reads therefore cannot consume route updates. The local defender can use internal routing through its validated actor identity; it has no commander seat or delivery cursor.

Match exposes an explicit refresh_world_visibility phase, which runs existing unit visibility and updates canonical building ghosts and local-defender visibility. Terrain refresh reads the current vision-pass fog mask; it does not advance vision. Wreck discovery and removal instead query current positions, spatial candidates, vision range and line of sight. Route live membership and fires are cached once per tick per owner. Existing referenced unit positions and health update on repeated reads, and retain_removed_world_route_unit preserves final removed-unit fields until the next cache rebuild. Wetness follows the current canonical value on every route read.

refresh_world_memory updates accepted terrain. world_terrain returns a full or incremental commander read; world_regions returns remembered region rows; world_wrecks returns remembered wreck rows. refresh_world_routing performs the memory-to-route transform and live filtering, then world_routing borrows query, knowledge, live hazards and route wrecks. Callers can split the remaining Match fields while these immutable facts are borrowed. None of these methods selects authoritative terrain as a substitute for unknown or remembered cells.

Rows include initial terrain, biome, landmark and explicitly borrowed canonical rail/station metadata only after discovery. Unknown mines remain hidden even during reveal. Accepted row identity changes only when source content changes. Cover basis is captured with accepted rows and is excluded from the source identity comparison. Unknown World cells keep zero flags and heights, zero remembered health and a separate unknown bit. Navigation versions change only when flags or height change, or when the first team binding is established.

The World journal has one checked absolute base and retained prefix. Trimming follows the source 65,536-entry threshold, minimum consumed team cursor and forced trim above 1,048,576 entries. A lagging team refreshes its full visible view after a forced trim. Memory change-log trimming follows the source size threshold; lagging route and commander cursors fall back to full remembered insertion order. Arithmetic errors reject before rows or journal prefixes change. Legacy ordinary take_journal keeps its drain/reset behavior; World startup calls the explicit zero-epoch reset before publishing dynamic structures.

Region knowledge preserves the source ownership and visibility rules. Formerly owned regions remain remembered after unseen loss, while progress, capper and contested values freeze out of view. Locks read currently visible or remembered production buildings. Explored territory runs group raw region-map indices, then source region rows look them up by authored ID. Signed or nonconsecutive IDs can therefore yield mismatched or empty runs; this behavior is retained explicitly.

The original JavaScript recorder contains three real createGame traces and 111 actions, including 6,200 accepted same-cell changes, both journal thresholds, teammate delivery, full reads, hidden mines, unseen edits, reveal toggles, raw region labels, canonical building ghosts, local routing, wreck memory and live route caches. It uses x64 Node 24.21.0 at the exact clean reference pin. Compact fingerprints include accepted revisions and ordered rows; route fingerprints include float32 health and trench-front bits. Native debug/release and atomic checks are pending.

This is internal World knowledge for the bounded logistics-disabled startup. Full World mode scheduling, capture/income/defeat/victory, command dispatch, recovery HUD, worldMapFor serialization, server snapshots, AI observation delivery and wire/ABI contracts remain separate. The current canonical Game has no skipFog field; this producer supports its actual reveal and ordinary visibility states, not a new skipFog policy. No scaling claim is made.
