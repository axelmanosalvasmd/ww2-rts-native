# Ground support tick provider

`match_ground_support.rs` prepares the three canonical ground support kinds for the sole Match tick runner. `validate_ground_support_tick(boundary)` is read-only: it checks the next boundary, canonical player/support metadata, pending plane supports, coarse strikes and on-map aircraft. It leaves the recorded queue, wallets, story, timers and RNG unchanged. Unknown names, malformed inputs, cooldowns and insufficient funds retain the existing parser and admission behavior. Future-boundary orders remain pending.

`step_ground_support_phase(captured_late_ids, dt)` delegates strike execution, then cover and cooldown decay. The tick caller must place it after flights, grenades and salvos, before scenario and living weather. Membership is captured before separation, as in `sim.js:5585-5637`. With aircraft excluded, the intervening source anti-air phase has no target. An uncut allied radio uses the ownership from before this tick's point updates. Cooldowns keep their negative values, including for away, out or finished players. New cover zones decay in their activation tick. Smoke lifetime and drift remain later weather phases. Events remain in the sole `SupportState.events` buffer.

Default and Conquest share ordinary support admission only when actual `Game.mode` is absent. Air supports, paratroopers, on-map aircraft and coarse `Game.strikes` remain unsupported before command consumption or clock advancement. A captured actor removed before the strike phase retains the existing component's explicit unsupported error. A failure after earlier tick phases must use the runner's existing fault contract.
