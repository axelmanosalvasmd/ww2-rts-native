# Native Conquest recruitment

`Match::recruit` connects the reviewed purchase and produced-unit helpers to the canonical Match. It rejects winner/away/out admission first, then preserves the source faction, Classic-only, naval, tier, MP, Fuel, population and unit-limit checks before selecting an owned, living, finished producer. `from` selects that exact eligible producer; an invalid selection gives `needs`. Without `from`, source unit order chooses the first maker. IDs remain monotonic, and placement scatter uses the unit collection's size, including dead entries still present.

A prepared purchase keeps the existing wallet exclusively borrowed. Placement, immediate rally routing and the new unit's control row are staged before payment. Every typed failure leaves the wallet, ID counter, unit table, grid and control rows unchanged. Commit charges source MP once, inserts the actual Unit, updates the maintained grid, publishes its canonical UnitControl and advances the ID. The source initially indexes its scatter pose and then moves that same record to the door exit; direct staged insertion at the final pose preserves the resulting insertion order. The blocked placement fallback remains a successful source placement, even when it overlaps or has no free cell.

Placement faces the building rally, else the personal rally, else map centre. Building rally routing takes precedence over personal routing. Owner-bound `RecruitRouting` checks the actual `ObservedMemory` producer identity, slot, team, ordinary observed mode and map dimensions. Its query contains remembered terrain, and its live fire/bunker/weather facts must already follow recipient policy. A missing or mismatched rally query fails before payment. An unreachable or expansion-limited source search still creates and charges the unit with an empty path; goal and rally drift remain. The source's fractional-bank recovery cannot change this produced-unit route because the initial point is a cell centre.

`Match.commands` owns live aim, automatic ability/retreat switches, rally drift reason and route end, alongside the command intent fields shared with the command actuator. `Unit` retains the actual pose, health, path, world goal, drift truth and spawn-ghost deadline. Recruitment metadata records only immutable producer, initial rally kind and initial search status. It does not duplicate live position, health, control switches or route destinations. Later statistics can use the returned exact spend.

The oracle executes the original `command`, `produceUnit`, spawn, door placement, observed route search and spatial updates at `e4e579a`. Six traces and 33 buy commands compare MP, IDs, HP, pose/aim/ghost bits, paths, goals, route ends, automatic switches and grid query order. They include source command gates, maker selection, personal/building rallies, ground and naval production, population refusal, disconnected rallies that still buy and an unrelated negative-HP casualty awaiting removal. Separate transactional tests cover missing/wrong recipients, exhausted or colliding IDs, air rejection and ambiguous pending supports.

This actuator supports immediate ground/naval Conquest recruitment only. Air-base initialization remains a distinct unsupported placement error, not a game-rule denial. The legacy `Strike` shape identifies Recon but merges other supports; pending ambiguous `Other` strikes reject rather than silently omitting paratrooper population. Known Recon contributes zero and already-live supports reserve no pending population. Canonical support identity, automatic visibility collection, source story spending, paid training completion, other modes, full combat initialization and public snapshots/ABI remain separate integrations. The server's match-start refusal is unchanged.
