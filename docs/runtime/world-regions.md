# Bounded native World region phase

`Match::apply_world_capture_income` runs explicit World income and region capture on an undecided authoritative Match. It accepts nonnegative finite simulation time and the tick's ordered unit IDs. The caller maintains the live spatial grid and advances the clock. This actuator does not enable the full World tick.

Income runs before capture, as in the pinned tick. Upkeep reads the supplied tick list, while node payments resolve current authoritative depot facts through `advance_income_with_depots`. A new depot can pay without joining the older upkeep list; a removed depot cannot pay through an old row. The original `advance_income` remains a convenience wrapper for callers whose unit view also represents current depots. This Match actuator requires every tick ID to remain represented in Game; retained removed tick facts need a future explicit producer input.

The region pass reads current production buildings and queries live infantry in maintained grid order. Guard-base locks are distinct from a neutral actor's ordinary production building. Mixed teams contest; riding, retreating and forced-reserve units cannot capture. Region progress drains to neutral before filling, with the first allied infantry owner receiving the capture story. Runtime centers and relocated homes use the original half-cell offset. Signed geography IDs stay separate from region vector indices.

`WorldRuntime.regions` remains the sole owner of team, progress, capper, contested, locked and capture-time fields. Wallets remain in the existing economy, counters in story and mutable commander homes in `start.players`. The recipient producer still computes its own visible/remembered production locks; authoritative lock flags do not replace that privacy policy. Canonical region fields have source startup defaults, with locked and capture time absent until written.

The actuator prepares wallets, regions, homes and story changes before publishing anything. Eligible fort transfers, elimination of a commander's remaining units or buildings, and World/draw/nations finishes return explicit unsupported errors for the entire operation. Gate state, wrecking/removal and common finish publication need their canonical adapters first. Already-decided matches and logistics-enabled World are also outside this boundary. Invalid identities, shapes, numbers and duplicate tick IDs return errors without phase mutation; nonfinite derived income is rejected before publication.
