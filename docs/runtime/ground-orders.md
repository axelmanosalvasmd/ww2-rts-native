# Ordinary ground orders

This source checkpoint adds ground Attack and Retreat to the existing recorded command path for typed Default and Conquest. It preserves the source selection cap, owner/operative/structure/rail/riding exclusions, forced and stranded permissions, follow cancellation, repeated IDs and eight waiting orders. Visible dead targets remain admissible; an unarmed selection returns QueueFull after source follow clearing. Accepted ground replacements remove paid Dig and shared project membership through their sole owner without refunding either.

Command::Attack has one target ID and an optional normalized waiting anchor. Raw JSON x/z do not create that anchor. A successful queued attack records the target admission pose, while the actual later command, live pursuit and visible owner plan read the current target. The owner waiting row uses kind 4 and falls back to the recorded anchor only when the target is missing or hidden.

The explicit phase is Match::apply_ground_attack. Its read-only guard is validate_ground_attacks. The sole tick owner must attach it after attack-move and represented fireAt, before reactions and movement, and report GroundAttack only after attachment. Aimed nade bypass, missing/hidden intent clearing, the existing firing claim actuator and the existing deferred FIFO are retained. No second scheduler or target authority exists. The existing Unit.attack Boolean is synchronized as a movement projection of control.attack_id.

Retreat prepares the physical exit first, selects the source home from that exited pose and stages actual recipient routing before accepting the complete group. The route search uses the canonical search history fork and owner-bound terrain, never hidden terrain as a fallback. Publication reuses the existing retreat reset, publishes routeEnd and clears retry failures as source findPath does. Garrison Attack uses the actual physical nearest-free MOVE cell when canShoot fails. Garrison Retreat prepares actual nearest-free MOVE exits and replaces each existing actor by its canonical ID in the first sight view. Later per-unit routes retain that first cache frame and refresh only the existing live poses. Future-ID spawn observers cannot represent that exit. The canonical gameplay grid is updated only at the accepted physical commit.

The original recorder is harness/ground-orders-fixture.mjs. Run it with WW2_REFERENCE pointing to the clean pinned reference and Node x64 24.21.0; --check regenerates and compares the committed deterministic gzip. The capture contains 28 cases, 48 commands, 30 complete source steps and 110 states. Setup restores declared quiet controls and explicit poses before commands. The recorder retains every startup ID and observes maintained spatial buckets without rebuilding them. Recorded output is never applied to the simulation.
