# First-person effects follow-up

This follow-up is source written and awaits its assigned native checks. The verified bounded entry/movement/respawn phase is separate in PR #120. No network, C or Unreal integration is enabled here.

`squad_men` retains the original drawn infantry slots, health-to-body count, rotation and velocity/9 lag. `companion_ray::trace` prepares the source fixed-distance 0.2 m sampled ray from exactly two supplied fractions, radius first and azimuth second. It tests only delivered owner visibility, skips dead/riding/air targets, preserves source target and drawn-man order, and lets friendly bodies stop the ray without an enemy hit. Smooth terrain, periodic LOS and body height use the canonical core helpers.

`Match::fire_companion` consumes the match's recorded Combat stream and canonical soldier, firing and combat fields. It stages randomness and damage before publishing ammo, cooldown, shot time and companion counters, so rejected state cannot partially spend a shot. Generic hurt shares the existing damage formula, suppression, attribution and rider handling. FPS adds its existing hit metadata without projectile armor, shooter XP, retarget reset or radial death impulse. Hurt precedes the ordinary small-arms event. The typed projection retains only the existing source shot fields and does not adopt the pending hit-direction representation.

The original-source fixture currently records 39 fire traces, nine grenade launch/trajectory traces, one carried-target hurt trace and 39 squad geometry cases. It includes 66 operations, 78 controlled spread draws and 77 trajectory samples. The carried-target case records Hurt at (40.25, 40.75) before disembarkation places the rider at (43, 41), with shooter XP and the existing death impulse unchanged. The source recorder retains intermediate mutation order; the native public API exposes returned events and final state, so native replay must state that observational limit.

The grenade adapter has the checked canonical typed ability-flight dependency and awaits its combined native verification. It currently accepts explicit Conquest mode, matching the shared physical-flight driver; the default mode alias remains unsupported for grenade launch. It retains pitch-driven range and duration before clipping the landing point to the map. Launch consumes no random draw and finishes before FPS decrements its grenade count or sets cooldown. Physical settlement and delayed blast remain with firing and combat. The recorder excludes grenade settlement and whole ticks. Recorded host Join/Input dispatch remains a coordinated command-queue extension, and full scheduling, presentation and complete-match acceptance remain separate.
