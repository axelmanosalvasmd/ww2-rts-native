## Bounded implementation sequence

First incorporate accepted constructor/metadata, World observation and split tail providers into a new isolated descendant of the sole caller. Keep the ordinary branch byte-stable where no adapter changes are needed. Before changing shared interfaces, obtain the actor/damage, path/observation, production and lifecycle owner readbacks for the exact affected bodies.

Then prepare one read-only World admission policy from the existing canonical owners. Admit a quiet, logistics-disabled, no-active-rail/air/operative/fort-transfer scene only after all reached ground timer, visibility, path, recovery and ordinary-death operations use that actor policy. An empty component should follow its real source conditional; never swallow a mode error and continue. Extend supported command/training/construction cases only as their actual adapters and before-clock guards become reviewable.

Attach the World tail at its exact source positions: final captured income, real convoys, current-region updates. Keep TickFailure and chronological events as the sole partial-result mechanism. Retain actual birth and removal records through the existing owners, with no cloned live-world history or second mutable phase state.

Finally replay original complete steps through one advance_tick call per source step. Compare actor timers/poses and guard-home behavior, command outcomes, real births, captured/current memberships, raw wallets, region/home/out changes, story/finish, ordered effects and actual seeded native stream consumption. Source fixed Math.random and authored environment seed establish reproducible source scene inputs; they do not establish equivalent native random history. Every unsupported scene needs meaningful whole-admission preservation coverage. A source recorder or bounded quiet replay alone is not full World gameplay, performance or server admission proof.
