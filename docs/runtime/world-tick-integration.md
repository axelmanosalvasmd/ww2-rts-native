# World tick integration boundary

This is a source-order plan for extending the existing Match controller. The ordinary Conquest controller remains the sole owner of command admission, prior poses, the clock and phase dispatch. World startup and explicit World capture, income, elimination and finish evidence do not establish a complete native World tick.

The pinned `shared/sim.js:5305-5770` runs structure synchronization and captures flight prior poses before incrementing the clock. Operative respawns, falling debris, periodic story sampling, weather planning, vision, research and shared work precede unit turns. Unit turns can create new units. At line 5605 the source captures its late unit list, before separation and flight/support effects. Late living weather, fire, flood and recovery use that captured list. Ordinary death removes current Game objects but leaves their object references in the list. Commander income then reads those final captured objects. The actual convoy phase follows income and may create later units. Finally `stepWorld` reads current production, current grid infantry and current armies, then applies homes, elimination and finish.

A future World adapter must retain both collections: ordered late objects, including actual final retired facts, and complete current live IDs after convoy effects. It must not reconstruct missing late objects from current Game or add later convoy births to upkeep. The current bounded region adapter resolves every tick ID through Game and explicitly refuses missing IDs. Supporting the source death boundary therefore requires caller-owned captured unit facts, including queue data where economy needs it, supplied by the sole tick/death owners. Current depot lookup remains separate and authoritative. A combined income/region call is valid only while the intervening convoy phase has no effects; logistics-enabled integration needs the actual income and post-convoy region sites without charging income twice.

World's local defender is an actor outside commander seats. Source `g.players[-1]` participates in live unit lookup and guard behavior, while array commander loops exclude it from research, income and results. Native uses the existing `LOCAL_DEFENDER_OWNER` and borrowed World actor accessor. World admission must validate that actor policy before consuming a queued boundary or changing the clock. Every reachable command, reaction, firing, recovery, production and visibility operation must use its real mode-aware owner adapter. Existing Conquest-only execution guards remain until those paths are verified.

The source sets point supply false for World even when requested (`createGame`, line 746). Logistics uses `worldSupply`, with region edges, damage, float32 costs/rates and armed-team occupancy. The ordinary ground supply network cannot stand in for it. Logistics-enabled World startup remains refused by the bounded constructor. Static rail metadata is represented, but active train travel, station departures, cargo and rider effects require their own actuators. Required fort seizure also remains a phase refusal. These are concrete admission failures to detect before queue publication and clock mutation, rather than alternate callbacks or partial mode dispatch.

`harness/world-tick-fixture.mjs` traces the unchanged original controller using observational module hooks. It requires the tracked-clean reference pin and x64 Node 24.21.0. Seven real constructor traces run 114 actual ticks and record 1,486 phase entries. They cover local actor membership, disabled point supply, two regional-network update ticks, a real post-list convoy birth, pre-capture income, nations elimination/finish and retained ordinary-death facts. The restored capture and shortage inputs are explicit scene facts; they do not alter source phase bodies. The fixture also records periodic sample counts before unit turns and the terminal sample after World elimination. Assertions reject missing witnesses and incorrect relative order. This is source evidence only: no Rust controller comparison, whole-match result claim or performance measurement is made.

The next acceptance boundary is an actual World mode branch inside the existing controller, after root and the tick owner approve the captured-facts input. It must reject unrepresented actors, supply, rails, cargo, work and capture consequences before the command/clock boundary. Admitted cases must compare source phase membership, income, region changes, out/home changes, story and finish while preserving the existing Conquest tests. Full World acceptance additionally requires the remaining adapters and seeded whole-match outcome checks.
