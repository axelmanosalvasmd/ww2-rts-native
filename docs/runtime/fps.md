# First-person companion runtime

The internal Match phase keeps the pinned ordinary Conquest companion rules. It changes no C or network interface and does not enable first person in the Rust server or Unreal client.

`Match.companions` stores ordered opaque identities, accepted input, edge counters, respawn times, vertical motion and loadout state. Canonical `Game::Unit` owns positions, horizontal velocity, HP and suppression. `UnitControl` owns aim, following and autonomous switches; `FiringState` owns cooldown; `CombatState` owns damage attribution and XP. Companion keys are interned in admission order as nonzero IDs for the existing numeric follow field. New units use the shared ordinary scatter and batch publication primitive, with no separate allocator or grid insertion path.

Call `respawn_companions` after advancing the simulation tick, before movement. Dispatch living operative-tagged units to `step_companion` and omit their ordinary movement, autonomous firing and reinforcement phases. Input is live for five ticks; stale/offline input decelerates the soldier. Grounded state is sampled before jumping and gravity, and collision applies x before z. Weapon switching and reload timing retain source order. A new squad press selects or releases the nearest eligible infantry within a strict eight metres, breaking equal distances by unit insertion order. Following calls the canonical ordinary attack-move actuator every five ticks, then restores its companion identity after the command's ownership filter. A routing infrastructure error during that accepted command aborts the tick; the runner must not retry a partially applied phase.

Before canonical death retirement, call `prepare_companion_deaths` for the ordered unit list. Run canonical retirement, then apply `companion_died` to the IDs in its returned retired records. The hook clears the controlled soldier and input, keeps squad/press memory, and sets the respawn time to tick plus 160. It leaves unit removal, rewards and other cleanup with retirement. Each eligible online companion respawns in admission order, first from a led nongarrisoned, noncarried squad with HP strictly above one man's health, otherwise for ten commander MP. Paid respawn uses the commander’s recorded spawn location without checking for a live HQ; the companion takes no army seat. The first admitted soldier is free, and paid respawn does not update recruitment spending. Preparation validates the whole batch before wallets, squad HP, unit tables, grid or metadata change.

`Companion::disconnect` clears input and leaves the soldier present. `reconnect` resets input sequencing and press baselines while retaining the soldier, squad and last-input tick. Room admission and role capabilities have pure helpers; identity authentication, room membership, pause/name/resync messages and the 20 ms wall-clock input throttle remain caller-owned transport work.

Fire and grenade requests identify the controlled unit and accepted aim input. Their ray selection, damage, spread RNG, projectile launch, ammo/counter changes and effects are explicitly pending combat integration. Unsupported requests create no shot or wire record. Full tick orchestration, logistics-enabled startup, save loading, snapshots, Unreal prediction/presentation and whole-match acceptance remain separate. The proposed hit-direction privacy representation is not adopted.

The original-source recorder appends private exports and the exact anchored respawn, death and reconnect blocks without editing the pinned reference. Seventeen traces provide 536 operations, including nonlexicographic companion admission and simultaneous respawn payment. Complete represented rows, wallets, input/edge state and finite float bits are retained. Every snapshot records six spatial probes with ordered, unordered and heavy queries, plus owner queries, to compare the maintained index after movement, placement and death. Separate original server blocks provide eight admission and eleven dispatch cases; server clock/pause gates remain source-only evidence. Native verification is pending the assigned shared Cargo slot.
