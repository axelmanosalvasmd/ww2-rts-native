# Shared field projects

This checkpoint supports ordinary Conquest field projects through the existing recorded command owner and `Match.field_works`. It adds no transport or C interface. Native checks and full runner assembly remain pending.

`FieldWorksRuntime` owns unpaid project segments, membership and paid Dig records. `Game.Unit.entrench` mirrors membership, and `Game.Unit.dig` mirrors the paid descriptor. Listed project iteration matches the source Map; a deleted project remains internally available while membership or paid work still refers to it. The prepared segment token borrows the canonical wallet and commits proportional payment with the actual job. No second terrain, health, wallet or job owner exists.

`Command::Entrench` holds normalized New or Join intent. Invalid pattern/material/coordinates remain typed refusal inputs, so ordinary denials retain source follow-clearing behavior. Native defensive errors publish no control changes. Queued orders store a singleton Join identity and the actual first unpaid point in the same per-unit queue. `project_goal` returns the first unpaid point or the unit pose while another paid segment remains active; empty finished membership does not block the next waiting order.

The runner calls `recount_field_projects` in the source early project beat, before queued orders and paid allocation. Active counts are recomputed each beat from living paid workers. Every twentieth tick, listed projects are swept and crews recounted from current membership and waiting Join references, including dead memberships until retirement. A free squad then calls `apply_project_unit` immediately before the existing `apply_field_work_unit`. The latter has a shared supplied-interval component method for source fixtures; the runner keeps its fixed interval.

Accepted replacement and retirement use `cancel_field_work`, removing paid work and membership before clearing their flags, without refund. A retry-limit Dig route drop uses `drop_field_work_job`: only the paid descriptor and Dig flag disappear. Membership survives, and cached active changes at the next recount. Cleanup preflight must validate both descriptor and membership projections before a batch removes its first unit.

Line, zigzag, double, arc, ring and strongpoint preserve source order and front angles through core math. Supported line materials are trench, sandbags, wire, traps, mines and known-mine clearing. Fill and concrete project work remain explicit Unsupported; bridge, Gun Pit, Hospital and Gate are not source line-project materials. Construction and other modes remain excluded.

The pinned original recorder covers 216 plans, 40 prices and 25 traces (137 actions, 162 snapshots), including actual unreachable routing with retry limit one. Native tests target 168 supported plans, 30 prices and 23 Match traces (131 actions); one direct-helper trace remains component-only and one Wall tier trace verifies the explicit provider exclusion. Observer-held unreferenced project objects are filtered from the test projection, while all operational listed and paid/member identities are compared. This is source evidence and written native coverage, not a passing native result.
