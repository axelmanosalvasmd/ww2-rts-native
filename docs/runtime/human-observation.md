# Detached ordinary human observation

`Match::human_commander_observation(&mut HumanObservationMemory)` produces `HumanView<commander_ai::Observation>` for one commander on an ordinary two-tick delivery or winner-forced final boundary, using the existing canonical vision phase. The packet retains every existing strategic Input field: dimensions, tick, seat, player team/out/spawn facts, public unit rows and owner-only plans, points, characters, flags, manpower and optional own research. Additional human facts carry own decoded move/attack-move goals, actual delivered visibility order and ordered original-view sightings.

The producer's private HumanObservationMemory belongs beside the existing seat commander, outside Match. It retains actual seen enemy nonstructures for 60 seconds, in Source Map insertion/update/expiry order. It also retains the actual ai-view stationary position/since map, with immediate visibility removal and the original 0.1-metre tolerance. The existing quiet strategic packet does not consume firstStillAt; delivery of that field to a broader artillery policy remains a separately reviewed type extension. HumanState separately owns camera-seen timestamps and attention. Reset both owners explicitly at handover; neither is a public snapshot or save format.

The strategic packet builder is shared with the existing opening producer. Its old wrapper retains its behavior. The new human producer stages the canonical recipient routing/Fog component and its private view memory, validates all packet facts, then commits the observation receipt and sole memory owner. It does not clone Game/Match, drain terrain send cursors, search paths, advance vision or use a simulation random stream. The human planner must rebuild its filtered strategic Input only from the owned packet and camera-filtered rows. Raw command Values remain private planner/input facts until canonical parsing and queue admission.

Publication rebinds the existing canonical path cache to the prepared recipient arrays after all fallible checks. It preserves that recipient's incremental history and unrelated cache identities without searching or cloning the path cache. The private memory binding requires an explicit reset at handover or a new match; its live array address, shape and seed do not establish identity after allocator reuse. The getter commits one seat, so all-wanted-seat admission and adaptive server delivery remain separate host work.

`human_screen_observation(&ScreenView<Observation>)` performs that rebuilding for the current strategy. It checks row identities/order and all shared delivered facts, retains only the camera-filtered rows, and keeps the remaining packet fields unchanged. It rejects forged row replacements and inconsistent visibility without consulting Match. The original screenView/remember helpers exercise camera-edge and retained-camera-memory cases in the same replay.

`Match::human_commander_control(owner, level)` reads current canonical out and finish even when a delivered view is old. `Match::human_commander_hurts(owner, generation, shots)` selects real owner hurt rows from a borrowed complete typed event frame. The caller supplies its actual replacement generation and event order. Non-hurt rows still occupy their raw ordinals; appending does not reset the cursor. Existing Firing, Support and Environment adapters borrow current typed facts without copying or draining a global event store. Complete mixed-frame assembly remains caller-owned.

The source fixture invokes unchanged ai.observe/viewFor readers and the unchanged ai-human hurt admission expression. Four ordinary Default/Conquest scenes, with and without Tech, contain 48 views and three append/reset hurt frames. They cover canonical sight, own plan precedence and public rounding, allied rows, hidden and rediscovered enemy sightings, strict expiry, stationary tolerance/reset, known authored mines, optional research and an odd-tick final delivery. Two additional route-history scenes record 24 original findPath queries across accepted edits, same-key observations and a second recipient. The four native replay, alert identity/ordinal, detached privacy/refusal and route-history tests pass on Linux, Windows and macOS at `ccfa01753d922efa3107d697b2c60d5a7cf751ee`, as part of the [401-test final-head run](https://github.com/axelmanosalvasmd/ww2-rts-native/actions/runs/38480198544). That source merged through PR #196 at `92fb7fe66eb7f788c83449ae67223984b969f177`. This verifies the bounded component tests; Human behavior approval and host scheduler integration remain separate.

This is the complete observation seam needed by the represented human wrapper and existing strategic packet, not a full strategic policy or a Match AI scheduler. Canonical construction target identity, off-map AIR, World/other modes, save/restore and transport remain separate. Later source changes need their own fresh platform checks. Admitted nonfinite hurt z coordinates are rejected before publication; no wire, C ABI, reference pin or policy contract changes are included.
