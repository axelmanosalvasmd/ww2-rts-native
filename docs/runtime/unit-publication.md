# Prepared unit publication

`StagedUnit::ordinary` reuses the source scatter and unit initializer, then optionally replaces the final point. It accepts the canonical player's spawn, explicit ID and scatter index so a caller can prepare a complete source-ordered respawn batch. Mutable drafts allow HP and control overrides before publication validation. Produced units can supply their already placed Unit and control instead of repeating scatter or door logic.

`prepare_publication` receives disjoint mutable references to units, grid, controls, recruitment metadata and the allocator. It checks the whole contiguous batch, ID headroom, canonical existing identity/order, owner/kind, finite geometry/HP and control metadata before returning a guard. The guard holds those fields exclusively, while wallets, story, firing and reserves remain independently borrowable. Dropping it publishes nothing. An existing squad's post-payment HP can be validated and staged through the guard; HP changes wait until publication.

`SpawnActor::Commander` resolves an ordinary player slot and supplied canonical spawn. `WorldLocalDefender` uses the one shared internal actor identity without creating a player or wallet, and requires actual World mode. `prepare_world_publication` explicitly checks World mode and allows that named actor alongside commanders; the ordinary publication wrapper still accepts only commanders. World ability costs and neutral guard overrides remain with World startup, staged before final validation. Canonical `UnitControl.guard_home` defaults to absent and is finite when supplied. Its World snap-back phase remains a tick integration, not execution implemented by publication. This actor policy does not implement World startup itself.

Publication consumes the guard, applies staged HP, inserts each unit in source order, maintains the grid, inserts canonical controls and optional recruitment facts, then advances the allocator. An infallible callback publishes already prepared metadata owned by firing, combat or reserves. Those owners must complete fallible validation and reject stale metadata for every new ID before payment. They must not duplicate unit position or HP. This primitive implements no purchase price, FPS eligibility or game-rule override itself.

Three focused regressions check whole-batch rejection/drop, staged squad HP with disjoint payment and ordered grid/control/ID publication, and explicit World actor admission with finite guard-home validation. The original recruitment oracle has six traces and 33 buys, including an unrelated casualty at negative HP that must not block publication. The existing original spawn oracle also regenerates unchanged.

The implementation passes 130 workspace tests, five release transaction/recruitment tests, strict workspace Clippy and formatting. Independent review reran the five focused tests and original recruitment regeneration with no remaining findings. Full FPS/World execution and future training integration remain separate; those consumers must preserve their own metadata preflight and publication callbacks.
