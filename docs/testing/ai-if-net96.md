# NET-96 native worker supervision

Reference: `e4e579a`, `server/shards.js:1-62`, `server.js:32-35,802-813` and `test-shards.js:26-37`. This change covers the room-routing, worker-isolation, directory, match-execution and worker-lifetime intent of NET-96. It adds no public message type or command admission.

`WW2_SHARDS` selects 1-64 workers. Each worker owns a separate OS thread, current-thread Tokio runtime, Hub and socket task set. The front decodes the existing room query and transfers the upgraded socket to FNV-1a(code) modulo N. The ordinary socket loop uses that same decoded code for every `hello` and later message. Both maintenance panics and socket-task panics end that worker; its supervisor starts a fresh incarnation after the one-second restart delay. Front shutdown or cancellation signals the worker runtimes to stop. Completed shutdown joins every supervisor and worker thread.

The front serves existing HTTP health and map handlers and merges existing room-directory projections in worker order. Upgrades are accepted only at `/ws`. Worker failure discards that worker's rooms and connections; no failed simulation tick or faulted room is retried. A restarted worker accepts fresh rooms on the same code-to-worker mapping. The existing R1 code-bound, private-room policy applies to all workers, preventing off-shard room joins from broadening trusted admission. World hosting and logistics guards are untouched.

The JavaScript `shardOf` function was imported directly from the pinned read-only prototype and evaluated on the Vostro. The 45 returned integers are the literals in the hash test. No behavior recorder or fixture bundle was introduced. Runtime intent tests use native state and real sockets.

The prototype's `ready {port}`, `record {key, run}` and `maps` messages are private process IPC. Native threads use private channels rather than replaying TCP upgrades between processes. Immutable embedded maps need no invalidation message, and native Horde record persistence remains unavailable. This change does not invent or implement those separate contracts. It makes no claim to recover live matches after a process-wide abort.

The worker loop uses Tokio's default fair selection. Fixed priority with maintenance before requests could starve new sockets and directory queries whenever maintenance consistently exceeded the ten-millisecond timer period. The independent source reviewer confirmed that cooperative yielding does not change that branch priority. The loop still checks shutdown before every selection. This correction adds no worker or Match state.
