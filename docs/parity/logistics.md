# Logistics (LOG)

Scope: unit reserves, shortages and withdrawal, territory supply, supply stores, trucks and convoys, allied relief, point supply lines, upkeep, and the logistics parts of the client. All paths are relative to `reference/ww2-rts` at e4e579a. "Live" means a server room; "headless" means `createGame` called directly (tests, tools).

The standalone reserve helpers are ported in `rust/crates/core/src/logistics.rs`, with original-JavaScript fixtures for 60 enablement contexts, 118 definitions, 708 initializations and 618 state/stock/query steps. This covers the pure reserve portions of LOG-01 through LOG-10 and LOG-15. Match initialization, movement/combat call sites, withdrawal actions and convoy service are not connected by this slice, so the rows remain pending integration.

## Rust objective phase evidence

`objectives.rs` provides sequential capture updates and point-supply connectivity from explicit live-unit, player and terrain facts. The original JavaScript oracle covers 214 capture traces (1,165 checkpoints) and 223 supply states, comparing progress bits, qualifying unit order, contest status, capture events, enemy-control/reached masks and cut flags. All unit kinds, allied ownership, ordered prerequisites, forced reserves, bridges, height changes, control/free-zone boundaries and naval blockers are included. Four focused tests pass in debug and release on the Mac.

The component does not schedule phases, disable supply by mode, apply capture story events, add income or decide a winner. Match wiring and territory refill networks remain incomplete. The affected rows stay in progress; see `DESIGN.md` for the exact capture-circle, supply-square and seed behavior.

## Existing limitations
- Logistics CPU is above its own target: about 25% of server CPU in the seeded 2-player, 2-AI World match, against a 10% goal (`docs/territory-supply.md:109-114`).
- No lobby control for logistics or point supply lines: `room.logistics` is never set by a lobby message (`server.js:381`, `server.js:419`), and `opts.supply` has no switch.
- Outside World Conquest, the overlay has no territory tint; only World region rates are sent (`shared/supply-convoys.js:654`).
- Away (disconnected) players lose spawn sources in modes without HQs and get no trucks or scheduling (`shared/supply-convoys.js:109`, `shared/supply-convoys.js:365`, `shared/supply-convoys.js:401`). This ties supply to connection state, which the server sets from sockets (`server.js:784`).
- Known fog leak, accepted in DESIGN: a "cut" point tells its owner an enemy stands somewhere on the road (`DESIGN.md:2225`). The cut flag is also sent to all players (`shared/sim.js:6068`).
- Dead code: World region relay stores (`store.region`, `u.regionCache`, `lostAt`) are never created now but their branches remain (`shared/supply-convoys.js:113`, `shared/supply-convoys.js:134`, `shared/supply-convoys.js:263`, `shared/supply-convoys.js:555`, `shared/supply-convoys.js:599`). The port can omit them without changing play.
- Seeded AI balance runs default to logistics off and tech off (`tools/ai-balance.mjs:56`, `shared/ai-schedule.js:52-56`), so most recorded AI balance does not exercise logistics.

## Doc and code contradictions
- Point supply lines start from spawns, not HQs. `DESIGN.md:2220` and the code comment at `shared/sim.js:4982` say the flood starts at HQs; `shared/sim.js:5005` floods from `pl.spawn`. A forward HQ does not extend point supply, and the flood still starts at a spawn whose HQ is gone.
- Territory overlay. `docs/territory-supply.md:95` says the overlay tints territory supplied, weakened and cut off; the client tints only World regions (`client/main.js:1812-1817`) because only World rates are on the wire (`shared/supply-convoys.js:654`). `DESIGN.md:175` matches the code.
- Dispatch budget wording. `DESIGN.md:144` says "at most 3 truck dispatches per tick"; the code limits route plans, including refresh repairs and retries (`shared/supply-convoys.js:458`, `shared/supply-convoys.js:463`, `shared/supply-convoys.js:471`).
- Zone of control detail. `docs/territory-supply.md:32-34` gives one rule; in code ground ZOC ignores retreating enemies (`shared/sim.js:4989`) but World region blocking counts them (`shared/sim.js:5057-5058`). Not a doc error, but the doc does not say it.
- Test list. `docs/territory-supply.md:119` and `:126` list tests ("a held point within 16 m keeps it open", "a cache refills nearby units from its stock while cut off") that no logistics test file checks directly; only `test.js` covers the point-cut exemption.
