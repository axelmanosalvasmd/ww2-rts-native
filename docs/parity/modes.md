# Modes and match flow (MODE)

Source: `reference/ww2-rts` at e4e579a. Evidence paths are relative to that folder. Units: seconds, metres, MP; one cell is 2 m; one tick is 1/20 s.

Conventions used below:

- There are seven mode kinds. Conquest is the default and runs with no mode object (`g.mode` is undefined); every other kind sets `g.mode.kind`. Code that tests `!g.mode` means Conquest.
- "Skirmish modes" are Conquest, Assault, Annihilation and Horde (`isSkirmishBaseMode`, `shared/sim.js:385`). "Construction modes" are Classic and World (`isConstructionMode`, `shared/sim.js:384`).
- "Seeded parity run" means the JS `playMatch` harness (`shared/ai-schedule.js:47-72`), which replaces `Math.random` with a seeded generator for the whole match, creation included. The native run uses the same map, names, teams, factions, options and seed, and must give the same winner, `endReason`, `endTick` and `endAt`.
- Economy, buildings and tiers are BASE rows; this section references them instead of repeating them.

## Existing limitations

- **Tutorial has no fail state.** Only finishing step 9 ends it; a player who loses every unit stays in a running match. `shared/tutorial.js:109-117`, `shared/sim.js:5770`.
- **Tutorial income comes from the Assault attacker base (5 MP/s)** because Tutorial sets no defender team. This looks accidental. `shared/sim.js:5751`.
- **Silent Conquest fallback.** createGame turns a Horde or Tutorial request that fails its conditions into Conquest. The server guards Horde's `defend` and the seat counts, so players do not hit it today. `shared/sim.js:686-688`, `server.js:373`.
- **Unseeded randomness.** `g.seed`, the spawn shuffle and combat rolls use `Math.random`; only the `playMatch` harness makes a match repeatable. The live server draws unrecorded seeds. `shared/sim.js:655-675`, `:772`; `shared/ai-schedule.js:53-54`; `server.js:381`.
- **Logistics and tiers have no lobby toggle.** They are fixed per mode; `room.logistics` and `room.tech` exist only through saves. `server.js:381`, `:419`.
- **Boss bar maximum counts living Kaiju only,** so a kill can raise the displayed percentage. `shared/sim.js:950-955`; DESIGN.md:728-729.
- **Kaiju and stuck Horde units.** Tank traps and rubble stop the Kaiju; a Horde unit with no route waits until killed; AI teammates do not hunt artillery shelling the bunker. DESIGN.md:717-720, :731.
- **Classic Sudden Death empties queues without a refund.** `shared/sim.js:5760`. Confirm before porting (it may be intended).
- **The report has no text for World end reasons** ('world', 'nations'), so the line reads "decided" with nothing after it. `client/report.js:8-10`, `:99`.
- **The Classic HUD tooltip lists HQ, Barracks, Motor Pool and Airfield,** but a Shipyard also keeps a player alive. `client/hud.js:216`; `shared/sim.js:355`.
- **Balance is not measured** for Horde on Massive, for late waves after the veterancy change, or after the projectile scaling fix. DESIGN.md:682-683, :711, :730.

## Doc and code contradictions

1. **World victory.** CONTEXT.md:9 says owning every region wins, and DESIGN.md:286 says winning requires all regions. The code wins at 60% of regions or as the last nation (`shared/world-conquest.js:17`, `shared/sim.js:1336-1347`), which matches DESIGN.md:270.
2. **Classic pop cap.** DESIGN.md:820 says 20; the code uses 24 (`shared/sim.js:166`).
3. **Production Buildings.** CONTEXT.md:70 and DESIGN.md:809 leave out the Shipyard; the code marks it `produces` (`shared/sim.js:355`), so it keeps a Classic player alive and locks World regions.
4. **"Annihilation" has two meanings.** CONTEXT.md:30 defines it as losing all Production Buildings (Classic's rule); the Annihilation mode eliminates on bunker loss (`shared/sim.js:5703-5707`).
5. **Horde map count.** DESIGN.md:667 says 11 of 22 maps have `defend`; at the pin 17 of 33 do.
6. **Trigger conditions.** DESIGN.md:2594-2595 says time is the only trigger condition; `shared/scenarios.js:108-123` implements ten more.
7. **Horde and points.** DESIGN.md:737 lists "a Horde that takes points" as deferred, but the capture loop does not exclude the Horde, so Horde infantry standing on a point should capture it (`shared/sim.js:5711-5725`). This comes from reading the code; not observed in a run.
