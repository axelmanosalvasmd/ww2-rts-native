### Details of the tools the harness builds on

**`tools/bench.mjs`.** Options: `--root DIR`, `--ticks N` (default 6,000), `--scenario classic|conquest|all` (default `all`: Classic on King of the Hill, then Conquest on Six Fronts), `--dump FILE`, `--map NAME` (`tools/bench.mjs:7-14,51`). For each scenario it replaces `Math.random` with a counting mulberry32 stream seeded `0x3c1055` before `createGame`, so spawn shuffling is seeded too (`tools/bench.mjs:25-34,53-55`). The game: six players `AI 1` to `AI 6`, `shuffle = true`, teams `[0..5]` (a six-way free-for-all), factions `i % 3`, army `massive` (`tools/bench.mjs:57-58`). Every seat is the root checkout's human-like commander on Normal (`tools/bench.mjs:24,62`); `aiTick` comes from the tool's own checkout (`tools/bench.mjs:22`). Each tick: `step`, `aiTick`, then on even ticks (or at a winner) one `snapshotCache` plus `snapshotFor` and `JSON.stringify` for all six seats, clearing `g.shots` and `g.newCells` (`tools/bench.mjs:64-92`). It stops early at a winner (`tools/bench.mjs:105`). It measures microseconds for tick, step, think, snapshot build, stringify and snapshot ticks (p50, p95, mean), snapshot bytes per seat, unit counts, path counters and random calls, and hashes `{ tick, winner, vp, mp, units: [id, type, owner, x, z, hp] }` sorted by id with sha256 (`tools/bench.mjs:107-131`). Determinism: verified (building blocks below).

**`drills/drill.js` format and `tools/drill.mjs`.** A drill module exports `about`, `map { w, h, spawns, rows? }` (rows default to open ground), `mode` (default conquest), `units: [{ owner, type, x, z, ...state }]`, `ai` (slots the commander plays), `warmup` and `seconds`, `script: [{ at, run(scene) }]` and `measure(scene)` (`drills/drill.js:1-11`). `runDrill` calls `playMatch` with `seed`, `shuffle: false`, teams per slot, factions `i % 3`, options `{ mode, weather: false }` and no army setting (`drills/drill.js:26-29`). In `setup` it clears all starting units and buildings, then buys each listed unit through `fixtureCommand` with MP raised to 1e6 and moves it to `(x, z)` with the extra state (`drills/drill.js:30-44`). Script steps run before `step` (`drills/drill.js:46-49`). `tools/drill.mjs` runs seeds `1..N` (default 100) per level and summarizes numbers by median and range, booleans as a share (`tools/drill.mjs:13-19`; `drills/drill.js:55-68`). Seeding: the global `Math.random` stream from `playMatch` (`shared/ai-schedule.js:52-54`); `drills/gap-column.js:33` also jitters start positions with it. Deterministic: `gap-column` with 3 seeds gave identical results twice.

**`test-fixtures.js`.** `fixtureCommand(g, slot, cmd)` forwards to `sim.command`, except a `buy` in a skirmish-base mode with no finished producer: it inserts a temporary built producer (id `-100 - slot`) at the spawn, buys, parks a bought plane at the fallback base, and deletes the producer before returning (`test-fixtures.js:5-21`). Population and price limits still apply. `clearFixtureUnits(g, which?)` removes units (all, or those `which` selects) and restores their footprint cells from `g.initialTerrain` (`test-fixtures.js:22-35`). `fixtureFactories` adds finished producers so AI tests see real choices (`test-fixtures.js:36-39`). No randomness of its own.

**`tools/balance.mjs`.** Three Normal AIs (commanders when the root has them), map `default`, mode Conquest or Classic, `n` matches (default 60) with seeds `seed * 100003 + i`, split across worker threads; each match seeds `Math.random` with mulberry32 before `createGame` (`tools/balance.mjs:36-43,101,114`). Caps at 40 minutes (Conquest) or 60 (Classic) (`tools/balance.mjs:36`). It reads `g.shots` each tick for behavior counters (rear hits, cover hits, AT on vehicles, MG on infantry, sniper on crews, crowding, lead changes) and clears `g.shots` every tick, not on the 2-tick beat (`tools/balance.mjs:54-71`). The commander reads shots incrementally each tick (`shared/ai-human.js:104-106`) and the sim reads only the shot it just pushed (`shared/sim.js:4739`), so this looks harmless; not proven. Output: JSON summary plus per-match results. Deterministic per seed by construction; not run here.

**`tools/ai-balance.mjs`.** FFA (one Normal seat per spawn the mode uses) or two-seat duels (`--seats easy,normal`, `old:` for the scripted planner, `alt:` for another AI file), `--rotate`, `--army`, `--factions 3|4`, `--teams`, `--logistics` (`tools/ai-balance.mjs:11`). Seeds: duels `(seed * 100003 + index * 7919) >>> 0`, FFA `seed + index`, mulberry32 over `Math.random` per match (`tools/ai-balance.mjs:46-47`). Caps at 1,200 s FFA, 1,800 s duels, 2,400 s Classic (`tools/ai-balance.mjs:41`). Uses the 2-tick beat and clears events on it (`tools/ai-balance.mjs:61-68`). Reports wins by seat, faction and spawn, draws, timeouts, median length and runner-up VP ratio.

**`tools/diag.mjs` and the recording format.** With `WW2_DIAG=1` the server appends one JSON line every 5 s per playing room to `logs/diag-<room>.jsonl` (`server.js:30`; `server/diag.js:1-4,10`). A line holds `t` (ISO time), `tick`, `tps`, `lateMax` (ms the server ran late), `loopP99` and `loopMax` (event-loop delay, ms), `tickP50` and `tickP95` (ms, from the tick meter), `snapEvery`, `units`, and `players`: `{ slot, ai: true }` for AI seats, else `{ slot, name, on, rtt, quiet, bufMax, client }`, where `client` holds the browser's `fps, worst, cpu, snaps, gap, kbs, ping, jitter, loss, mem, units, fx`, clamped to 0 to 1e6 (`server/diag.js:9,13-16,34-37`). A window longer than 7.5 s is dropped as a pause (`server/diag.js:32`). `tools/diag.mjs` reads a file (default: newest in `logs/`) and prints verdicts: server behind (tps p50 < 19, tick p95 > 40 ms, `snapEvery` > 2, loop stall > 100 ms), per-player network stalls or browser limits, and shared stalls (`tools/diag.mjs:7-40,42-48`). `test.js:6891` tests `summarize`. No randomness; output depends on wall time.

**`tickmeter.js`.** Rings of the last 200 tick samples (50 for snapshot ticks); every 1 s with at least 10 samples, a snapshot-tick p95 over 40 ms raises `snapEvery` (up to 4) and a p95 under 24 ms sustained for 10 s lowers it toward 2 (`tickmeter.js:11-15,21-42`). The live room sends snapshots and refreshes AI views only when `g.tick % room.snapEvery === 0` (`server/room-tick.js:14,21`; `shared/ai-schedule.js:31`), so a loaded server changes what its AIs see.

**`tools/bench-engine.mjs`.** `--ticks` 120 to 1,000 (default 160), `--out` (default `/tmp/ww2-engine-bench.json`), `--case`, `--profile` (V8 CPU sampling) (`tools/bench-engine.mjs:21-31`). Direct cases `quiet`, `crossing`, `bombardment`, `projectile`, `navigation`, `collapse`, `ai`, `horde` each run inside a mulberry32 `0x3c1055` stream (`tools/bench-engine.mjs:51-55`) with `shuffle = false`, army `massive`, weather and supply off (`tools/bench-engine.mjs:155-157`). The state hash rounds x, z and hp to 3 decimals (`tools/bench-engine.mjs:61`) and is marked comparable across runs (`tools/bench-engine.mjs:290`). Every snapshot payload per seat is hashed (`tools/bench-engine.mjs:262`) but the report keeps only three samples. Server cases import `server.js`, connect real WebSockets and are marked not comparable (`tools/bench-engine.mjs:411,443`). The report records sha256 of the inputs, Node version, flags and hardware (`tools/bench-engine.mjs:457-462`). Not run here.

**`tools/bench-move.mjs`.** Six Fronts, two players, `shuffle = false`, Massive, `Math.random` replaced by mulberry32 `0x3c1055` for the whole run (`tools/bench-move.mjs:21-33`). Replaces all units with 30 rifles and 30 light tanks cloned from a starting rifle onto open cells (optional 6 enemy bunkers), then `rebuildGrid` (`tools/bench-move.mjs:40-53`). Issues 32 alternating 60-unit move commands; records per trial the time, result, sha256 of every unit's route, path calls and expansions (`tools/bench-move.mjs:59-70`). Verified: two runs gave the same `inputHash` (`500c284eafae905a...`), route hashes and 133,376 expansions.

**`tools/bench-ground.mjs`, `tools/bench-world-conquest.mjs`.** The first times `client/ground.js` painting under a stub canvas (no randomness, client only). The second starts `server.js`, hosts a six-seat World Conquest room over real sockets, buys a mobile army per seat (default 64) and records tick phases, payload sizes and generation time with the server's own world seed (`tools/bench-world-conquest.mjs:1,16-19`). Neither gives a parity fixture.

**Movement lab.** `createMovementCase` builds a 64x64 map per scenario, creates a two-player game with weather and supply off, sets `g.seed = 7301`, clear weather, no points, `pathRetryLimit = 3`, clears units, places the unit(s) with hold fire and hold position, and schedules commands and terrain edits by tick (`tools/movement-lab-scenarios.js:32-160`). `runMovementCase` steps it and fails on unfinished arrival, spinning in place, hull or cliff violations, a moved protected blocker or missed queued stops (`tools/movement-lab-runner.js:24-75`). `tools/movement-lab.mjs` runs all 24 scenarios x 11 types at heading 0.15 and can write a report with traces (`tools/movement-lab.mjs:7-28`). `Math.random` is not replaced: `createGame` draws `g.seed` from it, which is then overwritten. `test-movement-lab.js:54-56` asserts two runs give identical results, and it passed.

**Terrain workshop.** Eight scripted pose scenarios on small authored maps or the generated World Conquest map (seed 20261003), driven along a fixed path without simulation (`tools/terrain-workshop-fixtures.js:5-45`). Presentation only.

**Map generators (`tools/genmap*`).** Each uses a Park-Miller generator (`seed * 16807 % 2147483647`) with fixed seeds and writes `maps/<name>.json` in place (`tools/genmap.js:14,40`; `tools/genmap-pack.js:14,47`). Running all eight in the scratch clone changed 15 committed maps in content, not just formatting (for example `six-fronts` 370 cells, `default` 886 cells, `king-of-the-hill` 424 cells, plus point lists on several). The committed maps were post-processed with `roads.mjs`, `woods.mjs` and `mapwork.mjs` (`tools/roads.mjs:4`; `tools/mapwork.mjs:11`) and possibly hand edits. The generators cannot rebuild the maps the game ships.

**Flaky risks.**
- Unseeded randomness: of about 160 inline checks that step a game, about 126 set neither `Math.random` nor a seed in their body. Many hold fire or need no roll, so most are probably stable, but `createGame` always draws `g.seed` from `Math.random` (`shared/sim.js:772`), so wind, weather timers and fire differ between runs (`shared/sim.js:773-775,2345`). `test-saves.mjs:17-18` steps 100 ticks unseeded before its seeded comparison; the comparison stays valid because both sides start from the same copied state.
- Wall clock: no test asserts on a measured duration (a scan of all test files found none; the "performance" files assert expansions, route hashes and pixel hashes, for example `test-path-performance.mjs:12-23,208-211`). The 20 child and socket server files and the 12 in-process server checks run real-time ticks and wait with deadlines (`test-socket.js:8-12`); child files time out at 180 s, the performance file at 240 s (`test-check.js:65,74`). These depend on machine load. All passed at load 11 to 16.

## Existing limitations
- The committed maps cannot be regenerated: 15 differ in content from their generators' output (TOOL-23). The harness must load `maps/*.json`.
- Live matches are not reproducible. `snapEvery` adapts to wall-clock tick cost (`tickmeter.js:31-40`) and AI views refresh on that beat (`server/room-tick.js:14,21`; `shared/ai-schedule.js:31`). Headless tools fix the beat at 2.
- `bench.mjs` loads `aiTick` from its own checkout and `sim.js`, `ai.js` from `--root` (`tools/bench.mjs:20-24`), so a cross-checkout comparison mixes AI schedules.
- `drills/gap-column.js:20` keeps state in module-level Maps, cleared at the drill's first script step; runs in one process are not independent if that step is skipped.
- Browser tests depend on one person's machine paths (`/tmp/ww2-fps-browser`, `/snap/bin/chromium`, `/home/axel`) and on Playwright, which `package.json` does not list (`tools/test-operative-browser.mjs:9,21`; `tools/test-public-lobby-browser.mjs:10`).
- `docs/` evidence was measured at older commits (manifests name `41eefe8`); none of it is an oracle for e4e579a.
- `start.cmd` hard-codes a tailnet host name (`start.cmd:8`).
- The 2026-10-12 bench runs were not benchmarks (a loaded machine, two runs in parallel), so only counts and hashes are reported.
