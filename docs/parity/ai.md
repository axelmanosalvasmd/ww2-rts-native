# AI commander (AI)

Scope: what an AI seat observes, how it orders, when it thinks, each difficulty, behavior per mode, fortification, the human-like commander, memory across save and load, and randomness. Paths are relative to `reference/ww2-rts` at e4e579a. "Planner" is `shared/ai.js` plus `shared/ai-mind.js`; "commander" is `shared/ai-human.js`, which wraps the planner for every seat AI. The Horde seat uses the planner alone.

Oracle note: the cheapest whole-AI regression check already exists in JS. `playMatch` (`shared/ai-schedule.js:52-72`) runs createGame, step and the server's AI schedule under one seeded `Math.random`, and the commander reports every input through `onInput` (`shared/ai-human.js:298`). The Rust port should emit the same input log so the two can be diffed tick by tick (AI-65).

## Existing limitations
- Live-server AI is not reproducible from seed and orders: the observation beat depends on wall-clock tick timing (AI-15), and the server never seeds `Math.random` or `g.seed` (`shared/sim.js:772`, `server.js:381`).
- Commander alerts come from the live `g.shots` list every tick (`shared/ai-human.js:103-117`), while a human receives the same events only on the next snapshot beat, so the AI can see own-unit damage up to 3 ticks earlier. The 0.2 s reaction floor hides most of it.
- Commander state is lost on save and load (AI-63); a loaded match replays the opening look for every AI seat.
- The planner assumes every queued order is accepted while it is still planning (AI-12), so a refused garrison or dig can leave a squad idle for that look.
- AI teammates in Horde stay within 70 m of home and do not hunt a mortar or rocket truck shelling the bunker (`DESIGN.md:717`).
- Seeded balance tools default to logistics off and tech off (`tools/ai-balance.mjs:56`), unlike live rooms.

## Determinism notes
- Random streams. (1) Global `Math.random`: unseeded V8 on the live server; `playMatch` replaces it with mulberry32(seed) for creation and the whole match (`shared/ai-schedule.js:37-71`). The planner shares this stream with combat (`shared/sim.js:4171-4172`, `shared/sim.js:4705`) and with `g.seed` at creation (`shared/sim.js:772`), so draw order is: `step`, then each seat's observe (Horde queue flush may issue commands), then each seat's act in seat order. (2) The commander's per-seat stream (AI-66), seeded from the current value of `g.seed`, which `rng(g)` advances on every weather and fire draw (`shared/sim.js:2345`). The seed therefore depends on the tick of the seat's first `tickCommander` call. (3) Weather and World generation use separate seeds (`server.js:365`, `server.js:381`).
- Draw counts matter, not only values: `spotNear` draws once per call (cover cell index or angle), and `shared/ai.js:1034` draws inside an object literal for every engineer in a non-depot build step. `test.js` counts draws in `aiCommands` (`test.js:4036-4046`).
- Scheduling: inside the AI all timing is in ticks (`TPS` 20) with no wall-clock reads (no `Date`, `performance` or timers in `shared/ai*.js`). The only wall-clock input is the server's adaptive `snapEvery` (AI-15) and the `away` flag set from sockets (`server.js:784`), which affects income and logistics, not AI seats directly.
- Iteration order: all collections are JS insertion-ordered Maps and Sets (`g.units`, `view.units` in snapshot row order, `mem.seen`, `mind.noticed`, `mind.roster`). Spatial queries return units in Map order (`shared/grid.js:56-59`, `shared/grid.js:110-111`). Sorts are stable (V8 TimSort) and many compare only distance, so ties keep input order. Rust needs insertion-ordered maps and stable sorts with the same inputs; `liveSightings` sorts by id, `onHeld` by distance then id.
- Float behaviour: distances use `Math.hypot`; angles use `Math.atan2`, `Math.cos`, `Math.sin`; comparisons use 1e-9 epsilons (`shared/ai.js:369`, `shared/ai.js:381`, `shared/ai-mind.js:70`, `shared/ai-mind.js:122`).
