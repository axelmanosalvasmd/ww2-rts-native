## Existing limitations

- The map design rules (walking-distance fairness, point safety, killing fields, lanes, dead space, sight lines) are measured only by `tools/mapstats.mjs` and partly applied by `tools/mapwork.mjs`. `validateMap` enforces none of them (`shared/sim.js:574-621`). Assault maps break the lane and choke rules on purpose (`DESIGN.md:2642-2644`).
- The two-sided mirrored maps (Ardennes, Twin Valleys, Polder, No Man's Land, Crater Field) are fair for two teams but not as a 4-player free-for-all: on Ardennes one mirror pair won 100 of 120 FFA AI matches. Left as is (`DESIGN.md:2654-2656`).
- Seating uses a 4-way walk with ford cost 6 (`shared/sim.js:633-647`), while the fairness tool walks 8 ways with ford cost 3 (`tools/mapstats.mjs:2`). `DESIGN.md:2615` says a 4-way walk overstates diagonal routes by about 40%.
- Map-file `mood` and `weather` are read (`shared/weather.js:38`, `:48`) but not validated, and the editor save drops them (`server.js:108-125`). No shipped map uses them.
- `test-arena` and `tutorial` appear in the map list of every mode (`server.js:52`; `client/main.js:391` disables maps only in Horde).
- The SHOAL band is computed once per match; a bridge built later does not move destroyers further off (`shared/sim.js:2666`).
- World generator has one landscape family: a fixed ridge band with passes at 0.22w and 0.71w, main rivers always north to south, the lake always on the first river at 0.68h, one region site per 64x64 block (`shared/world-landforms.js:7-9`, `:92-97`, `:130`; `shared/world-conquest.js:55-59`).
- Home selection has no fallback: if no free region has its nearest neighbour 50-70 cells away, `best` stays null and `best.home = i` throws (`shared/world-conquest.js:157-173`). A 2026-10-12 sweep of 80 maps (seeds 1000-1039, Huge and Massive, 6 players) raised no error.
- Rail track can run over fords: in the same 80-map sweep, 26 maps had 1-5 track cells on `F` (none on `W` or `B`). Costs test only the sampled 2-cell node (`shared/world-rails.js:12-13`) and the track is rasterized between nodes (`:89-93`).
- World generation is synchronous: 0.67-1.14 s per map in one run on this Mac while other sessions were active (seeds in MAP-94; not a benchmark). The docs record a 528 ms Huge median on a 4-vCPU EPYC host (`docs/strategic-world-generator-verification.md:58`).
- The World start map writes unknown cells as `.` and level `0`; only the delivered `cells` list tells a client what is discovered (`shared/sim.js:1445-1448`; `client/main.js:522-523`).

## Roadmap or unbuilt (excluded)

- More landscape families, topology repair or retry, a travel-time and economic fairness optimizer for homes, measured human pacing (`DESIGN.md:368-371`; `docs/strategic-world-generator-verification.md:73-78`).
- Arbitrary river orientations and a physical flow simulation (`DESIGN.md:337`).
- Map `triggers` with conditions other than time ("point taken", "area entered") and an editor control for them (`DESIGN.md:2594-2595`). The scenario system (MODE) may cover this.
- Spreading discovery terrain-mesh updates across frames (`DESIGN.md:261`).

## Doc and code contradictions

- Generator status: `DESIGN.md:332` and `DESIGN.md:355` label generator v3 and v2 "(unreleased)", but every World match runs it (`server.js:365`), the output says `generatorVersion: 3` (`shared/world-conquest.js:198`) and `CHANGELOG.md:987-989` ships it in the 2026-10-03 slice.
- `DESIGN.md:2657-2658` says `spawnDistances` ignores cliffs. The code blocks steps over 1 level (`shared/sim.js:644`), test "Spawn walking distances" (`test.js:123-128`) checks it, and `DESIGN.md:398` agrees with the code.
- `DESIGN.md:2598` lists "cells holding two things (a mine under a road)" as not done. Layered maps already store a mine over any dry ground (`shared/world-layers.js:16`, `:37-41`), and `test-engine-authoring.js:16-17` saves a mine over road `D`. No shipped map uses layers yet.
- Rails: `shared/world-rails.js:2` says lines "never ford or swim" and `DESIGN.md:304-305` says routing "avoids ... water and the 13 cells around each home objective". Measured: 26 of 80 maps put track on ford cells; the home zone is a +50 cost, not a hard exclusion (`shared/world-rails.js:23`).
- World win rule (MODE owns it): `DESIGN.md:270-272` and `shared/world-conquest.js:16-17` (`winShare` 0.6 or last nation with land) against `DESIGN.md:286-287`, `CONTEXT.md:9` and `docs/world-conquest-spec.md:19` (every region).
- `docs/world-conquest-spec.md:90` asks for an unknown-terrain representation distinct from real terrain; the start map uses the same `.`/`0` chars as open level-0 ground (`shared/sim.js:1445-1448`).
- `docs/world-waterways-verification.md:56` records a `shared/world-conquest.js` SHA-256 (`1c251e6d...`) that no longer matches the pinned file (`67161969...`, which added names, scenery and rails). The `shared/world-landforms.js` hash still matches.
- `DESIGN.md:334` calls the hydrology stream "independent". It is a separate generator instance, but it is seeded with the same value as the main stream (`shared/world-conquest.js:32`, `shared/world-landforms.js:22`), so both produce the same number sequence.
- Generator comments call the Pegasus Bridge crossings "stone" bridges (`tools/genmap-pack.js:53`, `tools/genmap-xl.js:39`), but neither map has a `buildings` entry, so they take plank-bridge hits (200 hp, `shared/sim.js:78`).

## Open questions for the owners

1. Coordinate mapping to Unreal (code leaves it open). The sim frame is x east (column), z south (row), height up; that triple is left-handed, like Unreal's X, Y, Z. Proposal: UE X = x * 100, UE Y = z * 100, UE Z = height * 100 (centimetres), so a sim angle atan2(dz, dx) equals UE yaw with no sign flip and map origin (0,0) is the north-west corner. A cell is 200 uu, a level 250 uu. Axel and Julio to confirm, including where the map origin sits in the UE level.
2. Should the Rust core own World generation (pure and deterministic, but it needs V8-equal `Math.hypot`, `sin`, `cos`, `atan2` and the exact heap tie order), or should the server keep a JS generator during transition? Parity needs bit-equal output either way.
3. Ship the 33 map JSON files as data and leave the `tools/genmap*` generators unported (TOOL)? The JSON files are the committed source of truth.
4. Rendered ground: must Unreal match `client/relief.js` `hAt` beyond MAP-57 (cubic ramps, ragged cliff rims, rock models), or is "centres exact, cliffs vertical, water depths as listed" enough for parity sign-off?
5. Runtime terrain edits (craters dent levels, bridges fall, trenches appear) need a ground mesh that updates per cell. Does Axel plan a procedural mesh rather than a UE Landscape?
6. Keep `test-arena` (and `tutorial` outside Tutorial mode) in the lobby map list, or hide them in the native client?
7. Should the fixed world fingerprints in MAP-94, plus per-map grid hashes (MAP-105), become committed parity fixtures (TOOL)?
