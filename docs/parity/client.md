## How to read this section

- **Columns** follow the other sections. "Rust / C ABI (Julio)" says what the row needs from the Rust side: an ABI call (an IF row), a protocol field or behavior from the Rust server (a NET row), or nothing ("none": a client-only rule or presentation).
- **Acceptance check**, by the rule in `PARITY.md`: **Test** for rules and pure client logic (an Unreal automation test or fixture against the pinned JavaScript); **Live integration** for protocol and privacy (against the reference server and later the Rust server); **Capture review** or **Playtest** for UI and content (reviewed screenshots or recordings, or a played session); **Measured gate** for performance (no benchmark was run for this file).
- **Status values used here:** `todo` (no Unreal code for the row); `in progress` (Unreal code exists for part of the row, or a placeholder stands in for it; unverified); `implemented-unverified` (Unreal code covers the row as far as source reading shows; its acceptance check has not been run and reviewed). No row is `accepted`. `implemented-unverified` is not in the `PARITY.md` vocabulary; the proposal is that it becomes `ported` when the row's check passes and `accepted` when both owners sign off.
- **Unreal citations** name the file (and lines where useful) that the status rests on. Several Unreal headers carry "Not ported" notes; where a header contradicts the code, the code was used and the drift is listed under "Unreal-side notes".
- Row IDs are stable from this draft on: a removed row is marked `dropped`, not renumbered.

## Existing limitations (reference client)

- The facing spots in every `move` order come from eased display positions (`client/main.js:1419,1925`), so two clients can send different orders for the same click. The Unreal client copies this (CLI-48).
- The report has no text for the World end reasons `world` and `nations`, so the line reads "decided" with nothing after it (`client/report.js:8-10,99`; `modes.md` limitations).
- The refused operative keeps reconnecting and shows "That order cannot happen", because `commander` has no sentence (`client/connection.js:23,51-54`; `client/availability.js:6-22`; `fps.md` limitations).
- Corpses, posture and the squad men's positions are client-only, so "the soldier you see is the soldier you hit" holds only roughly (`client/squad-motion.js:15`; `shared/squad-men.js:29-31`).
- The `d` numbers in latency pings are browser statistics (`client/perf.js`), which a native client cannot reproduce as they are.
- The placement preview ignores weather, treats planes as ground eyes and cannot see hidden units or mines (`client/availability.js:187-198`).
- The browser lowercases room codes; the server does not (`client/room-session.js:5`; `server.md` limitations).
- UK units speak with US voices: no `uk` voice folder exists (`client/audio.js:7-8`).
