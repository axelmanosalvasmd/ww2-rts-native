## Native multiple-fault admission order (owner R4)

[Axel approved R4 on issue #5](https://github.com/axelmanosalvasmd/ww2-rts-native/issues/5#issuecomment-6179562683): the first guard actually reached by native `Match::advance_tick` determines its refusal. This is an intentional native definition. Pinned `shared/sim.js` runs research at 5321, building training at 5352, worker collection at 5374-5379, aggregate construction at 5585-5603 and Legacy scenario at 5638. These live phases supply no equivalent global construction/production/scenario preflight order.

Current admission checks Legacy scenario before ordinary production and construction, before recorded inputs execute or the runner starts. Thus three independently invalid contexts already present at admission return the Legacy scenario refusal. The later post-command ordinary checks run construction, production, then Legacy scenario. The historical Legacy endpoint checked production, scenario, then construction there; neither later sequence overrides the earlier admission check.

The focused core regression uses genuine El Alamein startup and distinct waiting-Build, missing-production-building and invalid-scenario-owner defects. It checks each defect independently, all three together and all six direct read-only guard permutations, preserving the canonical queue, RNG, World and owner state. Failed admission returns empty events and default retirement without starting or faulting the runner. This core-only publication witness covers queued input, producer output and World publication state; it supplies no socket, frame or Unreal delivery proof. Runtime faults after successful admission retain their existing phase prefix and fault latch, rather than rolling the entire tick back. This note adds no parity row or completion claim.

## Existing limitations

- **Spectating gives full map knowledge outside World.** Any hello with a new token during a match becomes a spectator (up to 8) and sees every unit (server.js:204, 610; watchGame at server.js:217-221). A seated player can open a second tab with a different `&seat=` suffix and watch the enemy. There is no authentication; DESIGN.md:1530 says unlisted rooms are not authenticated or secret.
- **Room codes are case-sensitive on the server.** The server accepts `/^[a-z0-9]{3,12}$/i` and keys rooms by the code as sent (server.js:580-581, 590); the browser lowercases (client/room-session.js:5), so `ABC` and `abc` from a non-browser client are different rooms. The shard hash is also case-sensitive (server/shards.js:9-13).
- **Possibly stale wrecks outside World (unverified).** `trimmed` versions `wrecks` from the cache's global wreck list (server.js:237-242), but the list sent is the receiver's remembered wrecks (`rememberedWrecksFor`, shared/sim.js:1491-1497, 6048). A wreck a player discovers later is only sent when some wreck anywhere changes. No test covers it.
- **Owner-only flag mask drops more than stances.** For any row the receiver does not own, bits 16 (gate open), 17 (operative), 19 and 23-24 (cargo) are cleared (shared/sim.js:5903). Allies and enemies see open gates as shut and draw tank riders and operatives without their special handling. The uncached path keeps those bits (shared/sim.js:6044), so the two paths differ on them; CACHE compares rows only after this mask. Intent unverified.
- **Missed shots under backpressure.** A skipped seat's catch-up snapshot has no shots (server.js:774), so effects in skipped ticks never reach it. Terrain, fog and units catch up.
- **No backpressure for operative sockets.** `sendOperatives` sends without the in-flight check (server.js:320-328).
- **No general rate limit.** Only denials (4/s), map pings (3/5 s) and operative input (1 per 20 ms) are limited. Every `name` or lobby setting change rebroadcasts the lobby to everyone (server.js:638-681). DESIGN.md:1540-1541 lists rate limits, per-IP budgets and admission as missing.
- **No origin check and no authentication on the WebSocket.** `WebSocketServer` has no `verifyClient` (server.js:578); the token is a client-chosen secret.
- **Unknown message types during play produce a deny.** Any unrecognized `t` from a seated player reaches `command()` and returns `blocked` (server.js:712-715; shared/sim.js:3812), including a repeated `hello`.
- **One process runs all rooms in sequence.** A slow room delays the others (server.js:778-790); shards are the workaround. `MAX_ROOMS` is per process in shard mode (DESIGN.md:1573).
- **Lobby lists saves with a directory scan on every broadcast** (server/saves.js:39-49, marked "ponytail").
- **Saves are tied to Node.** The `.save` body is `v8.serialize` output (server/saves.js:18-22); it has no version field, and an AI memory that cannot be cloned is dropped silently (saves.js:21).
- **`room.logistics` and `room.tech` have no lobby message.** They are saved and passed to `createGame` (server.js:381, 419) but only tests set them.
- **Diag timing is process-wide.** `lateMax` and loop delay reset when any room writes (server/diag.js:27).
- **Map pings use wall-clock `Date.now()`** instead of the injectable clock (server/map-pings.js:8), so tests of the budget rely on real time.
