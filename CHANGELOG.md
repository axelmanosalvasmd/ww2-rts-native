# Changelog

## Unreleased

- Started the Rust workspace for issue #2: `rust/` with the `ww2-core` crate, pinned to Rust 1.99.0. Two pieces so far, each checked against the JavaScript game bit for bit:
  - `math.rs`: the core's own math, ported from V8's fdlibm (`sin`, `cos`, `tan`, `atan`, `atan2`, `exp`, `log`, `pow`) and `Math.hypot`, plus JavaScript's `round`, `max`, `min` and `sign`. 0 differences from x64 Node 24.21.0 over 1,000,000 inputs in each of 26 ranges. `pow` deliberately uses V8's fdlibm version on every platform, where Node calls the operating system's (different in the last bit for 6 to 10% of inputs).
  - `grid.rs`: the spatial index of `shared/grid.js`, with the same query order, including the bucket order unordered queries return. Matches a recorded log of 744 queries.
  - `harness/math-fixture.mjs` and `harness/grid-fixture.mjs` record the fixtures the two tests replay.
- Found: Node on Apple Silicon computes different last bits from x64 Node in V8's `sin`, `cos`, `tan`, `atan2`, `exp`, `log` and fdlibm `pow` (1,100 of 200,000 `Math.sin` values between -10 and 10), because clang fuses multiply-adds in V8's fdlibm on arm64. Reference runs that must agree, including every parity fixture, now use x64 Node (`DESIGN.md`, "The core's math"). The math table in `DESIGN.md`'s baseline is relabelled as measured against arm64 Node.
- Parity row statuses: MOV-65, MOV-66 (spatial grid), IF-15 (`hypot`) and IF-18 (`round`) ported; IF-16, IF-19 and IF-23 in progress; IF-17 (`pow`) differs.
