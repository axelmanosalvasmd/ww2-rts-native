# Changelog

## Unreleased

- Ported the vision pass and the fog pass to the Rust core, checked value for value against the reference. `ww2-core` gains `game.rs` (the game state as plain data: units, players and their teams and visible sets, the map's flags, heights and house kinds, structure cells, smoke clouds, strikes, weather), `rules.rs` (the unit kinds and vision numbers), `vision.rs` (`updateVision` with `visionOf`, `visionRange`, `reachDist`, `los`, `hillsClear`, `aimPoint`, `inStrip`, camouflage, trenches, dust, garrison houses, planes, recon flights, ships) and `fog.rs` (`teamFog` with `teamCells`, `fogTerrain`, `fogSource`, `fogLos` and the kept cells of still sources, plus a variant that works the teams out one thread each). Left out because Conquest does not use them: Horde stragglers shown through the fog, Classic and World Conquest's remembered buildings (`g.ghosts`), World Conquest's guards and its visible-cell list. The fog caches live in a `Fog` value beside the game, so the teams can run on separate threads (`DESIGN.md`, "Vision and fog in the core").
- New crate `rust/crates/simtest` (library and `simtest` binary): reads the harness's state files with `serde_json` 1.0.154 (with `float_roundtrip`, so every number parses to the same double as in JavaScript), decodes the codec's tags and builds the core's state. `harness/tables.mjs` dumps the unit, `CFG`, `SUPPORT` and weather numbers the passes read, so the Rust side loads the reference's own tables (IF-01 later). `harness/vision-check.mjs` and `simtest` print the same report: four passes per state (as saved, two passes standing still, then with the kept cells and fog terrain dropped), each player's visible ids, each team's fog hashes and version, and a hash of the kept cells.
- Parity: identical output for `bench-6000` (355 units) and `frozen-400`, `frozen-1000` and `frozen-2000`, with the fog on one thread and on one thread per team. The passes use `Math.cos` and `Math.sin` only for ships and live recon flights, which these states lack; arm64 Node printed the same lines as x64 Node on all four.
- Test: `simtest/tests/vision.rs` replays `tests/fixtures/vision.json` (128 KB, written by `harness/vision-fixture.mjs` with x64 Node): the bench match cut down to what the passes read, with snow, rain, a recon flight, snipers, woods, an unfinished Scout Tower, a church garrison, and a rider, a trench, smoke, dust, a building's aim point and a ship's hull each placed where the reference says they decide an answer. Breaking any of 28 rules in the Rust code on purpose fails it; four are not reached (the naval search radius, Horde bunkers, the aim point skipping fallen cells, smoke identity in the kept cells). `harness/state-codec.mjs` can now write typed arrays as runs, which keeps the fixture small; old state files read as before.
- Measured roughly on the Mac (Apple M3 Max, arm64 Node 24.21.0, rustc 1.99.0 release; busy, load average 10 to 14 on 14 cores, so not a benchmark), one vision pass plus the fog pass for all six teams, every source worked out again as when every unit moves, mean of 50 passes: 400 units 7.2 ms in JavaScript, 2.6 ms in Rust, 0.9 ms with the fog one thread per team; 1,000 units 13.3, 4.6 and 1.8 ms; 2,000 units 26.2 (p95 27.7), 8.4 (p95 9.0) and 3.8 ms (p95 4.2). At 2,000 the vision pass alone is 8.1 ms in JavaScript and 2.6 ms in Rust, and stays on one thread. Full table in `DESIGN.md`.
- Found and kept as the reference has it: the fog's sight walk (`fogLos`) ignores the woods depth rule that `los` applies, so the fog shows ground behind more than three woods cells as seen while a unit standing there is not (`docs/parity/combat.md`, limitations). Parity rows CMB-77, CMB-123 to CMB-128, CMB-131 and CMB-132 are in progress: the passes match the reference, the rows' own acceptance checks are not ported yet.

- Issue #2 harness, in `harness/`: `sim-state.mjs` replays the reference's Conquest bench match (Six Fronts, six Massive AI seats, seed `0x3c1055`) to tick 6,000, checks that it ends on the bench's final-state hash, and writes it and three frozen copies grown to 400, 1,000 and 2,000 units; `sim-workload.mjs` steps a frozen copy with no AI and times what the Rust core will port (movement, crowd separation, the vision pass, the fog pass); `state-codec.mjs` writes and reads a game as JSON, keeping Maps, Sets, typed arrays, -0 and fields set to `undefined`. The frozen copies hold still everything the port leaves out: nobody fires, nothing burns or flies, nobody digs or builds, no smoke, the weather and falling debris stand still, a path request keeps the current route, and units steer by the real map instead of each player's remembered view of it (rebuilt every tick from the cell log, which the port leaves out). Each run checks that no random number is drawn and the terrain never changes. Node module hooks do the timing and the stubs; nothing in `reference/` is edited. States go to `harness/out/` (ignored).
- Measured: the bench match ends on the same hash (`10267b84...`, 355 units, 39,377 random draws) under x64 and arm64 Node, so the last-bit differences in arm64's math did not reach this match. A first run on the Vostro, while it was loaded (load average 13 on 12 cores, so not a benchmark), put the JavaScript step at 9.0, 22.3 and 62.1 ms mean for 400, 1,000 and 2,000 units; at 2,000: movement 29.9, separation 15.4 and vision 14.6 ms, plus 28.9 ms of fog on vision ticks. The idle-machine numbers for #1 come with the Rust port.

- Started the Rust workspace for issue #2: `rust/` with the `ww2-core` crate, pinned to Rust 1.99.0. Two pieces so far, each checked against the JavaScript game bit for bit:
  - `math.rs`: the core's own math, ported from V8's fdlibm (`sin`, `cos`, `tan`, `atan`, `atan2`, `exp`, `log`, `pow`) and `Math.hypot`, plus JavaScript's `round`, `max`, `min` and `sign`. 0 differences from x64 Node 24.21.0 over 1,000,000 inputs in each of 26 ranges. `pow` deliberately uses V8's fdlibm version on every platform, where Node calls the operating system's (different in the last bit for 6 to 10% of inputs).
  - `grid.rs`: the spatial index of `shared/grid.js`, with the same query order, including the bucket order unordered queries return. Matches a recorded log of 744 queries.
  - `harness/math-fixture.mjs` and `harness/grid-fixture.mjs` record the fixtures the two tests replay.
- Found: Node on Apple Silicon computes different last bits from x64 Node in V8's `sin`, `cos`, `tan`, `atan2`, `exp`, `log` and fdlibm `pow` (1,100 of 200,000 `Math.sin` values between -10 and 10), because clang fuses multiply-adds in V8's fdlibm on arm64. Reference runs that must agree, including every parity fixture, now use x64 Node (`DESIGN.md`, "The core's math"). The math table in `DESIGN.md`'s baseline is relabelled as measured against arm64 Node.
- Parity row statuses: MOV-65, MOV-66 (spatial grid), IF-15 (`hypot`) and IF-18 (`round`) ported; IF-16, IF-19 and IF-23 in progress; IF-17 (`pow`) differs.
