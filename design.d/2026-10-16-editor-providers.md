## Editor acceptance and recipient building placement (2026-10-16)

Building commands and the internal recipient preview use one borrowed placement kernel from #336. Its inputs are dimensions, physical terrain, heights, occupied ground positions, resource nodes, sight, mode and placement restrictions. The recipient adapter accepts only decoded `ClientView` data. It reuses the canonical line-of-sight rule with delivered weather and grounded-aircraft flags, keeping the same sight intent as `shared/sim.js:1744-1751` and the placement reasons in `:3261-3313`. This supplies the fields omitted by the prototype's `client/availability.js:187-199` adapter to apply the canonical ordinary sight rule. Rounded recipient coordinates and hidden occupancy remain preview limitations; Build rechecks authoritative facts. No authoritative state, new recipient field or C interface is exposed. World recipient placement remains deferred, including every-cell sight, territory and railway constraints.

Editor validation and runtime admission serve different purposes. The editor accepts the prototype's loose detached World authoring metadata (`shared/sim.js:1139-1164`); runtime construction retains typed bounds and metadata checks. The save whitelist follows `server.js:106-126`, including its omission of `world`. An accepted World document can consequently become invalid after saving, exactly as in the prototype. Such files remain available through authenticated raw GET, use default catalogue metadata and fail strict runtime construction. Malformed optional persisted overrides follow the same recovery path. Running World rooms remain closed.
