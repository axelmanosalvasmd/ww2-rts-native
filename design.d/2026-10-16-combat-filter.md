# Capture recipient rows once per send

Delivery previously constructed a snapshot cache during each nested preflight
and again after publishing terrain and wreck memory. Carry owned immutable
unit, owner and public rows from the first preflight through publication, then
bind them to the final read-only Match borrow. These publications change
recipient delivery memory, not the captured gameplay facts. All selected
recipients and lazy terrain producers still admit before any publication.

A direct uncached projection builds unit rows from canonical state separately.
Both paths use the prototype cached-path flag mask approved by owner decision
P. This preserves one privacy rule while allowing meaningful cached versus
uncached comparisons. A test counts one cache construction for a complete
three-seat send and checks recipient order, repeated reads and mutations of
returned JSON. This is an allocation/ownership change; no timing improvement
is claimed.

The existing Classic building memory is already refreshed on real vision
ticks. Admit Classic to the internal snapshot cache so its existing six-field
ghost adapter can be delivered. This does not admit World or Classic network
startup and does not claim complete Classic economy, nodes or mode delivery.
