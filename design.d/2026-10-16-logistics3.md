## Ordinary scenario logistics and constructor weather seeds

LOGISTICS-3 composes the existing physical logistics and authored scenario owners with ordinary mode hosting. Scenario arrivals prepare their reserve state before canonical publication and install it immediately afterward. This keeps the same initial and reinforcement publication path while ensuring that no ordinary tick or recipient snapshot sees a logistics actor without reserves. Ordinary canonical mode pairing, World exclusion, side bounds, placement, population and type limits remain checked.

The server generates the prototype's 31-bit weather seed before construction and passes it explicitly in MatchOptions. Operating-system randomness stays outside the core. The existing host-private receipt records both the constructor seed and resolved weather seed, and checkpoints retain the deterministic resulting state. Weather seeds and scenario definitions do not enter public startup metadata. Fixed/map weather behavior remains selected by the existing weather planner. World size remains a deferred World-only constructor input.
