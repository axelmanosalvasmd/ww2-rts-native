## Room command union and Classic production snapshots

The server binds seated authority and queue identity, while the canonical core
owns command selection, mixed participants, mode checks and denial precedence.
Removing the old server ground-only filter lets the full ordinary prototype
command union reuse those owners without introducing a second actuator.

Internally attached Classic matches use the existing full room delivery path.
Admission validates canonical actor mode, elimination state and production state;
authored startup binding recomputes the elimination layout. World remains
closed. Classic node rows come from the elimination owner's nodes through one
projection shared by per-seat output and the room's global list cache. Currency,
production queues and refunds stay with the existing economy and production
owners. Waiting aimed abilities use the existing prototype order kind 6 and
owner privacy, including finite-coordinate and normalized-order checks.

Public Classic start remains guarded; hosted Horde keeps its separate start owner. This change enables the existing
internal attachment path to exercise production cancellation through actual
room commands and snapshots. No new wire shape or C ABI is introduced.
