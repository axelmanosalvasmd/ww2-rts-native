## Hosted Horde lifecycle and delivered brains (2026-10-16)

Hosted Horde reuses the canonical core tick, recipient producer, recorded input
queue and server ending hold. Its internal seat remains outside the lobby and
socket roster, as in the prototype. Startup and results include the canonical
internal player; presence arrays retain the lobby roster. Canonical admission
and snapshot preflights still run before publication.

A private optional authored-map directory lets Start and Restart reread a map.
The reader accepts only existing catalogue keys and refuses a missing or invalid
file without fallback. Match construction and startup binding use the same
validated value. The default embedded catalogue remains immutable. Preparation
finishes before runtime/account publication, so a removed defender list leaves
the previous match untouched.

The server feeds its real adaptive delivery beat to the existing shared AI
scheduler. Decoded recipient packets are retained across intervening callbacks.
Human commander and Horde policy adapters consume detached facts plus public
rules; they do not recover filtered authority. AI orders enter the next tick's
ordinary queue. No new wire fields, RNG version, FFI surface or World admission
are introduced. The existing aircraft weapon restriction protects complete
recipient delivery.

Ground abilities can retain flights, grenade tickets and salvo schedules across
snapshot beats. The recipient adapter validates those states before delivery,
projects only flights visible on the ground, and bounds extrapolation by fog
and visible static contacts. Throw events use the existing local event filter.
Aircraft weapons keep their existing restriction. Recorded AI support attempts
are restricted to the support kinds the hosted recipient adapter can deliver,
before payment or mutation.
